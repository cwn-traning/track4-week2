# guide-diagram · ออกแบบก่อนสร้าง (DESIGN.md)

ใช้คู่กับ **guide-oracle** · ขั้นนี้ **ยังไม่เขียนโค้ดเว็บ**

## Stack
ไม่ล็อก stack — ถามผู้ใช้ หรือใช้ที่ระบุใน REQUIREMENTS/โปรเจกต์เดิม ถ้าผู้ใช้ไม่มีความเห็น เสนอค่าเริ่มต้นที่พิสูจน์แล้ว:
web = Next.js (App Router, TypeScript) · db = PostgreSQL 16 · ทั้งคู่ใน Docker แยกโปรเจกต์ คุยผ่าน Docker network · e2e = Playwright
**บันทึก stack ที่เลือกไว้ต้นไฟล์ `docs/03-DESIGN.md`** (ขั้นถัดไปอ่านจากตรงนี้) · โค้ดจะอยู่ที่ `app/db/` และ `app/web/` (หรือ path ของเว็บเดิม)

## 5 ส่วนที่ต้องมี

1. **System Architecture** — เครื่องผู้ใช้ (เบราว์เซอร์ + เครื่องมือทดสอบ) → web → db
   ระบุชื่อ container, พอร์ตบนเครื่อง vs พอร์ตใน network (เช่น web ต่อ `db:5432` ส่วน `localhost:5433` ใช้จากเครื่องเราเท่านั้น), อะไรทำในเบราว์เซอร์ vs เซิร์ฟเวอร์
   ใต้ภาพ: ตาราง ชั้น | อยู่ที่ไหน | หน้าที่ | ทดสอบด้วยอะไร
2. **Use Case** — Mermaid ไม่มีชนิดนี้ ใช้ `flowchart LR`: actor = วงรี `((...))` "บทบาท (ชื่อคน)" ครบทุกกลุ่มใน interview + เจ้าของ/admin · ระบบเป็น `subgraph` · ทุก use case ใส่รหัส FR
3. **Flowchart** ≥ 2 รูปของ flow หลัก (เช่น ทำรายการหลัก, ยกเลิก) · ทุกจุดตัดสินใจเขียนรหัส BR กำกับ
4. **ERD** — ตาราง คอลัมน์หลัก ความสัมพันธ์ · เงินใช้ `NUMERIC` ไม่ใช้ float · แต้ม/จำนวนครั้งใช้ integer · Mermaid ERD ใส่ชนิดได้คำเดียว → เขียน `NUMERIC(10,2)` ไว้ในช่อง comment
5. **Sequence** ≥ 2 รูป: flow หลัก (เบราว์เซอร์ → web → API → db พร้อม transaction และ error เช่น 409) + flow ที่เปลี่ยนสถานะ/หักยอด

ท้ายไฟล์: **คำถามที่ได้จากการออกแบบ** (เรื่องที่ US/REQ ยังไม่บอก เช่น "หักครั้งตอนจองหรือตอนใช้", "ยกเลิกแล้วคืนไหม") — การวาด sequence มักเจอคำถามพวกนี้

## ข้อควรระวัง Mermaid
- ห้ามใส่ URL (`http://...`) เป็นป้ายบนเส้น → เขียน "localhost พอร์ต 3000"
- ป้ายที่มีวงเล็บ/เครื่องหมายพิเศษ ครอบด้วย `"..."`
- ภาษาไทยใช้ได้ แต่ id ของ node ใช้อังกฤษ
- **ตรวจว่า render ได้จริง**: ถ้ามี Node ใช้ `npx -y @mermaid-js/mermaid-cli -i docs/03-DESIGN.md -o <scratch>/out.md` หรือแยกแต่ละบล็อกไป render · รายงาน "render ผ่าน X/Y"

# guide-oracle · กติกากลาง

ประโยคหลัก: **"ลูกค้าขอ ≠ AI บอกว่าทำแล้ว ≠ เว็บทำจริง"** งานของ tester คือ **พิสูจน์** ไม่ใช่เชื่อ

## 1. โครงโฟลเดอร์ของโปรเจกต์ (บังคับ)

```text
<โปรเจกต์>/
├─ .claude/                      skills + commands
├─ CLAUDE.md                     คำสั่งเปิดระบบ + วิธีรัน test (/10)
├─ docs/                         📄 เอกสาร = แหล่ง [D] + การออกแบบ
│  ├─ 00-INTERVIEW.md            input จากลูกค้า
│  ├─ 01-USER-STORIES.md         /01
│  ├─ 02-REQUIREMENTS.md         /02
│  ├─ 03-DESIGN.md               /03 (บันทึก stack ไว้หัวไฟล์)
│  ├─ 04-TEST-DATA.md            /04 ← ส่งลูกค้ายืนยัน
│  └─ 05-BUILD-PROMPT.md         /05
├─ app/                          🌐 เว็บ
│  ├─ db/                        /06
│  └─ web/                       /06
│     ├─ SPEC.md                 แหล่ง [A]
│     └─ ASSETS.md
└─ playwright/                   🧪 สำรวจ · แผน · พิสูจน์
   ├─ 07-EXPLORATION.md          /07 (ส่วน A–F แยกหัวข้อย่อยตาม module)
   ├─ exploration/<module>/*.png /07 แหล่ง [O]
   ├─ 08-TEST-PLAN.md            /08 (1–5) + /09 (6–8) · TC-<MOD>-xx
   ├─ 08-TEST-RUN-1.md           /08
   ├─ 09-PLAN-REVIEW.md          /09
   ├─ 11-BUG-HUNT.md             /11
   └─ e2e/                       /10
      ├─ package.json · playwright.config.ts · tsconfig.json
      ├─ qa.config.json          ⚙️ ค่ากลางของโปรเจกต์ (ข้อ 2)
      ├─ core/                   ♻️ ใช้ซ้ำข้ามโปรเจกต์ (global-setup, fixtures, evidence, report/)
      ├─ tests/<module>/*.spec.ts
      ├─ test-report/<module>/gifs/ · videos/ · logs/
      ├─ triage.json
      └─ index.html
```

- ทุก path ใน command นับจาก **root ของโปรเจกต์** (cwd) · ถ้าโฟลเดอร์ยังไม่มีให้สร้าง
- **เว็บที่มีอยู่แล้ว**: ข้าม /05–06 · ให้ `qa.config.json` ชี้ `appPath` ไปที่โค้ดเดิม และ `specPath` ไปที่เอกสารของเว็บ (ใช้แทน SPEC = [A])
- **โปรเจกต์เดิมที่ไฟล์อยู่ root แบบเก่า** (USER-STORIES.md ฯลฯ): เสนอให้ผู้ใช้ย้ายเข้าโครงนี้ก่อน ห้ามย้ายเองโดยไม่ถาม

## 2. `playwright/e2e/qa.config.json` (แหล่งค่ากลาง)
สร้างครั้งแรกที่ /07 (รายชื่อ module ต้องให้ผู้ใช้ยืนยัน) · ทุกขั้นตั้งแต่ /07 อ่านค่าจากไฟล์นี้ ห้ามตั้งค่าซ้ำในที่อื่น
```json
{
  "project": "<ชื่อระบบ>",
  "appPath": "app/web",
  "specPath": "app/web/SPEC.md",
  "baseURL": "http://localhost:3000",
  "health": { "path": "/api/health", "expect": { "ok": true, "db": true } },
  "reset":  { "method": "POST", "path": "/api/test/reset", "nowField": "now" },
  "lockedNow": "<จาก docs/04-TEST-DATA.md>",
  "locale": "th-TH",
  "timezone": "Asia/Bangkok",
  "browsers": ["chromium", "firefox", "webkit"],
  "exit": { "p1": "all", "passRate": 0.95 },
  "modules": [
    { "id": "BOOK", "folder": "booking", "title": "จองคิว", "fr": ["FR-01"], "br": ["BR-01"] }
  ]
}
```
- `modules[].id` = ส่วนกลางของ TC ID (`TC-BOOK-01`) และ tag (`@BOOK`) · `folder` = ชื่อโฟลเดอร์ใต้ `exploration/`, `tests/`, `test-report/`
- ทุก FR/BR ต้องอยู่ใน module ใด module หนึ่ง (ยกเว้นที่ประกาศว่าไม่ทดสอบในแผนหัวข้อ 2)
- เพิ่ม/เปลี่ยน module ภายหลัง: แก้ไฟล์นี้ + บอกผู้ใช้ว่าโฟลเดอร์/TC ไหนได้รับผล

## 3. ป้ายที่มาของผลที่คาดหวัง (oracle)

| ป้าย | ฟังจาก | ไฟล์ | ความน่าเชื่อ |
|---|---|---|---|
| **[D]** ลูกค้า/เจ้าของงาน | interview, คำยืนยันของลูกค้า | `docs/01`–`04` | ✅ สูงสุด |
| **[R]** กฎทั่วไป | คณิตศาสตร์ สามัญสำนึก มาตรฐาน (เช่น logout แล้วต้องเข้าไม่ได้) | — ต้องเขียนเหตุผล | 🟡 ดี |
| **[A]** AI/คนสร้างเว็บ | คำอ้างของผู้สร้าง, โค้ด | `app/web/SPEC.md` · สรุปตอน build | 🟠 ต่ำ (ตรวจงานตัวเอง) |
| **[O]** หน้าจอ | สิ่งที่เห็นตอนสำรวจ | `playwright/exploration/` | 🔴 ต่ำสุด (เว็บอาจผิดอยู่แล้ว) |

**กติกา**
- ผลที่คาดหวังทุกข้อต้องมี **[D] หรือ [R]** รองรับ ถ้ามีแค่ [A]/[O] → ติด `[O-ยังไม่ยืนยัน]` แล้วเพิ่มเป็นคำถามถึงลูกค้า (เป้า ≤ ~20% ของ TC)
- **ห้ามอบบั๊กลงในผลที่คาดหวัง:** ตัวเลขเงิน/จำนวน/สถานะให้ **คำนวณจาก [D]+[R] ก่อนเปิดเว็บ** เสมอ ห้ามลอกจากจอหรือจากโค้ด
- ผลไม่ตรง → **ห้ามแก้ผลที่คาดหวังตามเว็บ** ให้ทำ ⚠️ แล้วจำแนก (ข้อ 7)
- ข้อความที่รู้จาก [A] อย่างเดียว เขียน expected แบบไม่ผูกคำ เช่น "มีข้อความแจ้งว่าใช้บัตรไม่ได้"
- ลำดับฟังเสมอ: **ลูกค้าก่อน → AI → หน้าจอ** กันถูกหน้าจอชักนำ

## 4. ค่าขอบ 3 ค่า
ทุกกฎที่มีตัวเลขต้องทดสอบ **ต่ำกว่า / ที่ขอบพอดี / เกินขอบ** (บั๊กชอบซ่อนที่ "ขอบพอดี")
เลือกข้อมูลทดสอบให้ "คำตอบผิด" ได้ตัวเลขต่างจาก "คำตอบถูก" ชัด ๆ (กัน oracle อ่อน)

## 5. Traceability
`00-INTERVIEW → US-xx → FR/BR/NFR-xx → module → TC-<MOD>-xx → test → BUG-xx`
ทุก US ต้องมี FR หรือ BR รองรับ · ทุก BR ในขอบเขตต้องมี TC อย่างน้อย 1 ข้อ

## 6. สมมติฐาน ⚠️
ค่าที่ลูกค้ายังไม่ได้บอกชัด → ติด ⚠️ + เขียนสมมติฐานที่ใช้ + โยงเข้าตาราง "คำถามที่ยังไม่ชัด" **ห้ามเดาเงียบ ๆ** · ไม่แน่ใจให้หยุดถามผู้ใช้

## 7. test ล้ม = ผิดที่ไหน (ดูภาพ/GIF ก่อนเสมอ)
| ทาง | อาการ | ทำต่อ |
|---|---|---|
| เว็บผิด (`web-bug`) | ผลขัด [D]/[R] | รายงานบั๊กให้คนสร้าง |
| test ผิด (`test-bug`) | หา element ผิด รอไม่พอ | แก้ test ได้ แต่ **ห้ามเปลี่ยน expected** |
| แผน/กฎไม่ชัด (`plan-issue`) | เว็บกับแผนถูก "คนละแบบ" | ถามลูกค้า แล้วแก้ docs / แผนก่อน (ยังนับเป็นล้มจนกว่าจะแก้) |

## 9. จุดตัดสินใจ: วิเคราะห์ → ถามกลับ → แนะนำ
เรื่องที่เป็นรสนิยมหรือการตัดสินใจทางธุรกิจ (ดีไซน์, stack, module, ขอบเขต, เกณฑ์ Exit) **ห้ามเลือกเองเงียบ ๆ** ทำตามลำดับนี้:
1. **วิเคราะห์ก่อน** จาก docs (ธุรกิจ ลูกค้าหลัก อุปกรณ์ ข้อจำกัด) — สรุปให้ผู้ใช้เห็น 2–4 บรรทัดว่า "จากเอกสาร ผมเข้าใจว่า…"
2. **ถามด้วยตัวเลือก** ผ่าน AskUserQuestion (ไม่มีให้ถามในแชทเป็นข้อ ๆ): ≤ 4 คำถามต่อรอบ · 2–4 ตัวเลือกต่อคำถาม · ตัวเลือกแรกคือที่แนะนำ ติด "(แนะนำ)" · ทุกตัวเลือกบอกผลที่ตามมา · ใช้ `preview` เมื่อต้องเทียบภาพ/โค้ด/พาเลต
3. **ให้เหตุผลของคำแนะนำ** ผูกกับข้อมูลจริงใน docs (เช่น "ลูกค้าหลักอายุ 50+ → ตัวอักษร 18px") ไม่ใช่ความชอบส่วนตัว
4. ข้อที่ docs ตอบชัดอยู่แล้ว **ไม่ต้องถาม** — แจ้งว่าใช้ค่าอะไรจากไหน
5. **บันทึกการตัดสินใจ** ลงไฟล์ผลของขั้นนั้น: ตาราง เรื่อง | ตัวเลือกที่เลือก | แนะนำไว้ | เหตุผล/ผู้ตัดสิน
6. ผู้ใช้ตอบ "แล้วแต่" หรือไม่ตอบ → ใช้ตัวที่แนะนำ แล้วจดว่า "ใช้ค่าแนะนำ (ผู้ใช้ไม่ได้ระบุ)"

## 10. มาตรฐานการเขียน
- ภาษาไทย ทับศัพท์ได้ (test case, API, data-testid) · ใน User Story ใช้ภาษาชาวบ้าน
- ผลที่คาดหวังเป็น **ตัวเลข/ข้อความที่ตรวจได้** ห้ามเขียน "แสดงถูกต้อง" · เงินแสดงวิธีคิด เช่น `฿800 − 5% (฿40) = ฿760`
- ทุกค่าต้องมาจากคำสั่งที่รันจริงหรือไฟล์จริง ห้ามแต่งผล
- จบทุก command ด้วย **ตารางสรุป** + "ไปต่อได้เมื่อ" + command ถัดไป

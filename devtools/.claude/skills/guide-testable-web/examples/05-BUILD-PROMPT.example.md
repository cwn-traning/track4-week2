## 0. อ่านก่อนลงมือ
- อ่าน `docs/02-REQUIREMENTS.md` · `docs/03-DESIGN.md` · `docs/04-TEST-DATA.md` ให้จบก่อนเขียนโค้ด
- ถ้าเอกสารขัดกัน ยึด TEST-DATA > REQUIREMENTS > DESIGN · ไม่แน่ใจให้ถามผม ห้ามเดา
- โค้ดอยู่ใน `app/db/` และ `app/web/` เท่านั้น ห้ามแตะ `docs/` และ `playwright/`

## 1. Stack
- web: Next.js 15 (App Router, TypeScript strict) · Tailwind CSS 4 · ไลบรารี `pg` เขียน SQL ตรง (ไม่ใช้ ORM)
- db: PostgreSQL 16 · ทั้งคู่รันใน Docker แยก 2 compose project คุยผ่าน network `daeng-net`
- ไอคอน: `lucide-react` ชุดเดียวทั้งเว็บ · ฟอนต์ผ่าน `next/font/google`

## 2. ฐานข้อมูล `app/db/`
- container `daeng-db` (postgres:16-alpine) · volume `daeng-pgdata` · พอร์ต `5433:5432` · healthcheck `pg_isready`
- `init/01-schema.sql` ตาม ERD ใน DESIGN (เงิน `NUMERIC(10,2)` · แต้ม/แก้ว `INTEGER` · มี `UNIQUE` กันออเดอร์ซ้ำจาก `idempotency_key`)
- `init/02-seed.sql` ตาม TEST-DATA **ทุกค่า** (ผู้ใช้ U01–U06 · เมนู M01–M18 · ออเดอร์ตั้งต้น O01–O04 · บัตรสะสม)

## 3. Backend + กฎร้าน
- API ใต้ `app/web/src/app/api/` · กฎธุรกิจรวมที่ `src/lib/rules/` แยกไฟล์ต่อเรื่อง ใส่รหัส BR ในชื่อฟังก์ชัน/คอมเมนต์ เช่น `// BR-04 ซื้อครบ 10 แก้วแถม 1`
- เงินคิดด้วย integer สตางค์หรือ Decimal ห้าม float · ลำดับคิดราคาตาม BR-09
- รายการที่สร้างข้อมูล (สั่ง, แลกแต้ม) ใช้ transaction + idempotency_key ฝั่ง client · error ตอบ `{ "error": { "code": "SLOT_FULL", "message": "..." } }`

## 4. Docker ของ web `app/web/`
- container `daeng-web` พอร์ต 3000 · `output: "standalone"` · `HOSTNAME=0.0.0.0` · `TZ=Asia/Bangkok`
- `DATABASE_URL=postgres://...@daeng-db:5432/daeng` (ไม่ใช่ 5433) · ห้ามต่อ DB ตอน build (หน้าที่อ่าน DB ใช้ `dynamic = "force-dynamic"`)
- healthcheck: `node -e "fetch('http://127.0.0.1:3000/api/health').then(r=>r.json()).then(j=>process.exit(j.ok&&j.db?0:1)).catch(()=>process.exit(1))"`
- เปิด db → รอ healthy → เปิด web · ไม่มีไฟล์ `.sh` · `.gitattributes` = LF · คำสั่งทุกตัวใช้ใน PowerShell ได้

## 5. รูปภาพ
- ห้ามใช้รูปจากเน็ต · เก็บที่ `app/web/public/assets/` · เช็ก `codex --version`
- มี Codex: `codex exec` สร้างรูปตาม Art direction ในขั้น 6.7 → คัดลอกจาก `~/.codex/generated_images` → ย่อด้วย sharp (hero 1920w + 960w, การ์ด 800w, WebP คุณภาพ 80)
- ไม่มี/ล้มเหลว: วาด SVG/CSS เฉพาะรูปนั้น (ใช้พาเลตจากขั้น 6.1 ห้ามสีนอกพาเลต)
- เขียน `app/web/ASSETS.md`: ไฟล์ | ใช้ที่หน้าไหน | ขนาด | สร้างด้วย Codex หรือ SVG/CSS

## 6. Design Brief (ส่วนที่ทำให้เว็บสวย — ทำครบทุกข้อ)

### 6.1 ทิศทางและ token
- อารมณ์: **"อบอุ่น · ไม้ · แสงเช้า"** ร้านกาแฟย่านเก่า ไม่ใช่ chain สากล · คำที่ห้าม: นีออน, gradient ม่วง-ฟ้า, glassmorphism
- ประกาศเป็น CSS variables ใน `globals.css` แล้วผูกกับ Tailwind theme · **ห้ามใช้สี hex นอก token ในคอมโพเนนต์**

| token | ค่า | ใช้กับ |
|---|---|---|
| `--bg` | `#FBF7F1` | พื้นหลังหลัก (ครีมนม) |
| `--surface` | `#FFFFFF` | การ์ด |
| `--ink` | `#2B1D14` | ตัวอักษรหลัก (คอนทราสต์กับ bg ≥ 12:1) |
| `--ink-muted` | `#6E5A4B` | คำอธิบาย (≥ 4.5:1) |
| `--brand` | `#B4412B` | ปุ่มหลัก ลิงก์ (แดงอิฐ) |
| `--brand-ink` | `#FFFFFF` | ตัวอักษรบนปุ่มหลัก |
| `--accent` | `#D9A441` | ป้ายแต้ม ดาว ไฮไลต์ (ทองน้ำผึ้ง) |
| `--line` | `#E8DED2` | เส้นแบ่ง ขอบช่องกรอก |
| `--ok` / `--warn` / `--err` | `#2F7D4F` / `#B7791F` / `#B42318` | สถานะ |

- ฟอนต์: หัวข้อ **"Mitr"** 500/600 · เนื้อหา **"IBM Plex Sans Thai"** 400/500 · ตัวเลขราคาใช้ `font-variant-numeric: tabular-nums`
- Type scale (มือถือ → เดสก์ท็อป): h1 32→48 · h2 24→32 · h3 20→24 · body 16 · small 14 · line-height เนื้อหา 1.6 (ไทยต้องโปร่งกว่าอังกฤษ)
- Spacing scale 4/8/12/16/24/32/48/64 · radius การ์ด 16 · ปุ่ม 12 · ช่องกรอก 10
- เงา 2 ระดับเท่านั้น: `--shadow-1: 0 1px 2px rgb(43 29 20 / .06), 0 2px 8px rgb(43 29 20 / .06)` · `--shadow-2` (hover/modal) เข้มขึ้น 1 ขั้น

### 6.2 Layout
- container กว้างสุด 1200px · gutter 16 (มือถือ) / 24 (แท็บเล็ต) / 32 (เดสก์ท็อป)
- breakpoint: 375 (ออกแบบก่อน — mobile first) · 768 · 1280 · ห้าม scroll แนวนอนทุกขนาด
- grid เมนู: 1 คอลัมน์ (375) · 2 (768) · 3 (1280) · ระยะห่างการ์ด 16/24
- header: โลโก้ซ้าย · เมนูกลาง · ปุ่มตะกร้า + ภาษาขวา · มือถือยุบเป็น ☰ + ตะกร้าลอยมุมขวาล่าง

### 6.3 หน้าหลักและลำดับสายตา (ทุกหน้าต้องตอบ "สิ่งแรกที่เห็นคืออะไร")
| หน้า | สิ่งแรกที่เห็น | โครง |
|---|---|---|
| `/` หน้าแรก | hero ภาพบาร์ไม้ + ประโยคเดียว + ปุ่ม "สั่งล่วงหน้า" | hero → เมนูแนะนำ 3 ใบ → บัตรสะสมของฉัน (ถ้า login) → เวลาเปิด/แผนที่ |
| `/menu` | แถบหมวด (sticky) | หมวด → การ์ดเมนู (รูป 4:3, ชื่อ, ราคา, ป้ายร้อน/เย็น) |
| `/order` | ขั้นที่อยู่ (stepper 3 ขั้น) | เลือกรายการ → เวลารับ → สรุปราคา (แยกบรรทัดส่วนลด/แต้ม ชัด) |
| `/account` | แต้มและแก้วสะสม (ตัวเลขใหญ่) | บัตรสะสม 10 ช่อง → ประวัติ → ตั้งค่า |
| `/admin` | คิวออเดอร์วันนี้ | ตารางคิว + ปุ่ม "ชงเสร็จ" |

### 6.4 คอมโพเนนต์และสถานะ (ทุกตัวต้องมีครบ)
- ปุ่ม: primary / secondary / ghost · สถานะ default · hover (เข้มขึ้น 6%) · active · **focus-visible (วงแหวน 2px `--accent` offset 2px)** · disabled (opacity .5 + cursor not-allowed + เหตุผลใต้ปุ่ม) · loading (spinner + ข้อความ "กำลังส่ง…" + กดซ้ำไม่ได้)
- ช่องกรอก: label อยู่บนเสมอ (ห้ามใช้ placeholder แทน label) · error สีแดงใต้ช่อง + ไอคอน + ข้อความคำต่อคำจาก SPEC · ช่องสูงอย่างน้อย 44px
- การ์ดเมนู: hover ยก 2px + `--shadow-2` · รูปมี `aspect-ratio` กันหน้ากระตุก
- **Empty state** ทุกรายการ (ตะกร้าว่าง, ยังไม่มีประวัติ): ภาพประกอบ SVG เล็ก + ประโยคเดียว + ปุ่มไปทำต่อ
- **Loading**: skeleton ขนาดเท่าของจริง (ห้าม spinner กลางจอทั้งหน้า)
- **Error ทั้งหน้า**: ข้อความสุภาพ + ปุ่มลองใหม่ + เบอร์ร้าน
- Toast ยืนยัน (มุมล่าง, 4 วินาที, มี role="status")

### 6.5 Motion
- ระยะเวลา 150ms (hover) / 250ms (เปิด/ปิด) · easing `cubic-bezier(.2,.8,.2,1)` · เคลื่อนที่ ≤ 8px
- การ์ดเข้า viewport จางขึ้นทีละใบ (stagger 40ms) เฉพาะครั้งแรก
- เคารพ `prefers-reduced-motion: reduce` = ปิด animation ทั้งหมด

### 6.6 ภาษาและเนื้อหา
- ไทย / English · สลับที่ header · ทุกข้อความอยู่ในไฟล์แปล ห้าม hardcode
- ห้าม lorem ipsum · ใช้ชื่อเมนู/ราคาจาก TEST-DATA · microcopy เป็นกันเอง สุภาพ ("รับได้ 08:30 นะคะ")
- ราคาแสดง `฿65` (ไม่มีทศนิยมถ้าเป็นจำนวนเต็ม) · เวลา 24 ชม.

### 6.7 Art direction ของรูป (ส่งให้ Codex ทุกรูป)
- สไตล์: ภาพถ่ายสมจริง แสงธรรมชาติจากหน้าต่างด้านซ้าย โทนอุ่น ไม้สีน้ำตาลกลาง เซรามิกครีม ระยะชัดตื้น ไม่มีตัวอักษร/โลโก้ในภาพ ไม่มีหน้าคนชัด
- ชุดรูป: hero 16:9 (บาร์ไม้ + เครื่องชง) · เมนู 4:3 มุมเฉียง 45° พื้นไม้เดียวกันทุกรูป (ให้เป็นชุดเดียวกัน) · ภาพบรรยากาศร้าน 3:2
- ทุกรูปมี `alt` ภาษาไทยที่บอกเนื้อหาจริง

### 6.8 Accessibility (ขั้นต่ำ)
- คอนทราสต์ตัวอักษร ≥ 4.5:1 (ตัวใหญ่ ≥ 3:1) · เป้าแตะ ≥ 44×44 · ใช้คีย์บอร์ดได้ทุกฟีเจอร์ · ลำดับ heading ถูก · `lang` ตามภาษา

### 6.9 Visual QA (ทำก่อนจบขั้น 11 — ห้ามข้าม)
1. ใช้ Playwright จับภาพทุกหน้าใน 6.3 ที่ 375 / 768 / 1280 → `app/web/design-qa/<หน้า>-<กว้าง>.png`
2. ตรวจทุกภาพตามเช็กลิสต์ แล้วแก้จนผ่าน: ไม่มี scroll แนวนอน · ไม่มีข้อความล้น/ตัดคำไทยผิด · ระยะห่างสม่ำเสมอตาม scale · สีอยู่ใน token เท่านั้น · ปุ่มหลักเห็นชัดใน 1 จอแรก · รูปไม่ยืด/แตก · empty/loading/error state มีจริง
3. เขียน `app/web/DESIGN-QA.md`: หน้า | ขนาด | ผ่าน/แก้อะไร

## 7. ฟีเจอร์
- ครบทุก FR ใน REQUIREMENTS (FR-01–FR-22) · ตัวเลขทุกตัวตรง BR และ TEST-DATA
- หน้า `/admin` ให้บาริสต้ากด "ชงเสร็จ" (ให้แต้ม BR-06 · นับแก้วสะสม BR-04) · บัญชี `staff@daeng.test` ⚠️ ไม่มีใน TEST-DATA ให้จดใน SPEC เป็นสมมติฐาน

## 8. ทดสอบได้
- `data-testid` ทุกปุ่ม ช่องกรอก ผลลัพธ์ ข้อความ error (รูปแบบ `kebab-case` เช่น `order-submit`, `price-total`, `error-slot-full`)
- `<html data-ready="true">` เมื่อ hydrate เสร็จ
- `POST /api/test/reset` (เปิดเมื่อ `ALLOW_TEST_RESET=1`) ล้างกลับเป็น seed < 1 วินาที · รับ `{"now":"<ISO>"}` ล็อกเวลา (ไม่ส่ง = วันล็อกใน TEST-DATA)
- นาฬิกากลาง `src/lib/clock.ts` ตัวเดียว ทุกกฎที่ใช้เวลาเรียกจากที่นี่
- "แนะนำเมนูตามอารมณ์" เป็นกฎตายตัว (ตารางใน BR-12) ไม่เรียก API ภายนอก

## 9. เอกสาร
- `app/web/SPEC.md`: หน้า + URL · กฎโยง FR/BR · `data-testid` ทุกตัว · ข้อความ error คำต่อคำ (ทุกภาษา) · API ทุกเส้น (method, body, status) · ผู้ใช้ seed · สมมติฐานที่ตั้งเอง ⚠️

## 10. ตรวจตัวเอง
- สคริปต์ `app/web/scripts/check-rules.mjs` ยิง API ตามตารางค่าขอบ E01–E48 ใน TEST-DATA แล้วรายงาน "ผ่าน X / Y" (นี่คือคำอ้าง [A] ไม่ใช่การพิสูจน์)

## 11. เปิดระบบและสรุป
1. เปิด db → healthy → เปิด web → healthy · `/api/health` ต้องตอบ `{"ok":true,"db":true}`
2. รัน check-rules · ทำ Visual QA (6.9)
3. เปิด http://localhost:3000 ให้ผมดู
4. สรุปเป็นตาราง: ส่วน | ผล (container · health · หน้า/API · testid · รูป Codex/SVG · Visual QA · check-rules X/Y) + สมมติฐานที่ตั้งเอง

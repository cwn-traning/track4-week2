> Codex: ไฟล์นี้สร้างจาก `.claude/commands/05-build-prompt.md` (อย่าแก้ตรงนี้ — แก้ต้นฉบับแล้วรัน `scripts/sync-codex-prompts.sh`) — ทำตามกติกาแปลงใน `AGENTS.md` หัวข้อ 0 ("โหลด skill `X`" = อ่าน `.claude/skills/X/SKILL.md` ทั้งไฟล์ก่อนลงมือ · "ถามผู้ใช้" = หยุดรอคำตอบ) และจบงานด้วย Completion report format ใน `AGENTS.md`


โหลด skill `guide-oracle` และ `guide-testable-web` ก่อน · ขั้นนี้ **ห้ามเขียนโค้ดเว็บ**

ต้องมี `docs/02-REQUIREMENTS.md`, `docs/03-DESIGN.md`, `docs/04-TEST-DATA.md` ถ้าไม่มีให้หยุดบอก command ที่ต้องรันก่อน
ชื่อระบบ/โทน: $ARGUMENTS (ว่าง = ใช้จาก REQUIREMENTS/DESIGN)

เขียน `docs/05-BUILD-PROMPT.md` ภาษาไทย ตาม template ส่วน E ของ guide-testable-web
- stack, ชื่อ container, พอร์ต อ่านจากหัว docs/03-DESIGN.md · โค้ดลง `app/db/` และ `app/web/` เท่านั้น
- ต้องสั่งครบ 6 สิ่งที่ทำให้ทดสอบได้ (ส่วน A) · seed ตาม TEST-DATA ทุกค่า · `app/web/SPEC.md` / `ASSETS.md` · รูปภาพไม่ใช้จากเน็ต
- **ขั้น 6 Design Brief ครบ 9 หัวข้อ** ตามส่วน D2 · ใช้ `examples/05-BUILD-PROMPT.example.md` ใน skill เป็นแบบระดับความละเอียด (ห้ามคัดลอกค่าของร้านตัวอย่าง)
- **ก่อนเขียน ต้องปรึกษาดีไซน์ตามส่วน D3** ของ guide-testable-web:
  วิเคราะห์จาก docs → สรุปให้ผู้ใช้เห็น → ถามด้วย AskUserQuestion (ทิศทาง 3 แบบพร้อม preview · แบรนด์เดิม · อุปกรณ์หลัก · ระดับลูกเล่น) ตัวเลือกแรก = แนะนำพร้อมเหตุผล
  → ถามรอบ 2 เฉพาะที่ยังไม่ชัด → เสนอตาราง token ให้ยืนยัน → ค่อยเขียน · บันทึก "การตัดสินใจด้านดีไซน์" ต้นไฟล์
  ถ้า argument บอกทิศทาง/แบรนด์มาแล้ว ให้ข้ามคำถามข้อนั้น · ถ้าผู้ใช้สั่ง `quick` ให้ใช้ค่าแนะนำทั้งหมดโดยไม่ถาม แต่ยังต้องบันทึกเหตุผล
- ทุก FR/BR ต้องถูกสั่งในขั้นใดขั้นหนึ่ง · ~150–250 บรรทัด มีเลขขั้น
- **ไม่มี BUG_MODE** (ใช้กับงานจริง)

สรุปเป็นตาราง: ขั้นในพรอมต์ | FR/BR ที่ครอบคลุม + FR/BR ที่ยังไม่ครอบ (ต้องเป็น 0)
ปิดท้าย: ขอให้ผู้ใช้ **อ่านตรวจ docs/05-BUILD-PROMPT.md ก่อน** แล้วเปิดเซสชันใหม่ (หรือ `/clear`) รัน `/06-build-web`
